# Plan M0 — Base del monorepo

## Contexto

Hoy el repo tiene solo docs (SPEC, CLAUDE.md, CONSTRAINTS.md, DECISIONS.md, floor-guard). M0 deja el esqueleto del monorepo andando para que M1 pueda arrancar con TDD sobre el motor.
**Criterio de aceptación (SPEC §12):** `pnpm dev` abre la web y se conecta al server (indicador "conectado").
Fuera de alcance de M0: motor, salas, fuentes/arte, Motion, Howler, CI (M8), deploy.

## Hallazgos que cambian versiones (van como ADR en la tarea 1)

- **TypeScript 6.0.x fijado, no 7.x**: `typescript-eslint@8.72` exige `typescript >=4.8.4 <6.1.0`. TS 7 (la versión nativa en Go) rompe el lint tipado.
- **ESLint 9, no 10**: `eslint-plugin-react@7.37` (lo necesitamos para `react/jsx-no-literals`, la regla del copy centralizado) declara peer `eslint ^9.7`.
- El resto en su última versión: Vite 8, React 19, Tailwind 4 (`@tailwindcss/vite`), Vitest 5 + `@vitest/coverage-v8`, Express 5, Socket.IO 4.8, Zod 4, Zustand 5, Prettier 3.

## Tareas (un commit Conventional Commits por tarea)

### T1 — Raíz del workspace · `chore: scaffold pnpm workspace`

- `package.json` raíz (private, `packageManager: pnpm@10.28.0`, `engines.node >=22`), `pnpm-workspace.yaml` (`apps/*`, `packages/*`), `.nvmrc` (24), `.gitignore`, `.editorconfig`, `tsconfig.base.json` (`strict`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`, `isolatedModules`).
- `docs/DECISIONS.md`: ADR-007 (TS 6.0), ADR-008 (ESLint 9), ADR-009 (shared se consume como fuente TS vía `exports`, sin build propio).
- **Verifica**: `pnpm install` sin warnings de peers.

### T2 — Lint y formato · `chore: add eslint and prettier`

- `eslint.config.js` flat: `typescript-eslint` (strictTypeChecked), `react`, `react-hooks`, `react/jsx-no-literals` solo en `apps/web/src`, `no-explicit-any` error, `eslint-config-prettier`. `.prettierrc`.
- Scripts raíz: `lint`, `format`, `typecheck` (`pnpm -r typecheck`).
- **Verifica**: `pnpm lint` y `pnpm typecheck` en verde (aunque haya poco código).

### T3 — `packages/shared` · `feat(shared): add package with health contract`

- Paquete `@clave/shared` con `src/index.ts` exportando el contrato de salud que usan web y server: `HEALTH_PATH = '/health'` y `healthResponseSchema` (Zod: `{ ok: true, uptimeSec: number }`) + su tipo inferido.
- `vitest.config.ts` del paquete; `vitest.config.ts` raíz con `test.projects` para correr todo con `pnpm test`.
- **TDD**: test del schema (acepta válido, rechaza inválido) escrito primero.
- Las carpetas `engine/ schemas/ types/ words/` se crean en M1, cuando tengan contenido.

### T4 — `apps/server` · `feat(server): add express + socket.io with /health`

- `src/app.ts` (factory `createServer({ clientOrigin })` → Express + HTTP + Socket.IO, testeable sin escuchar puerto), `src/index.ts` (lee `PORT`=3001, `CLIENT_ORIGIN`=`http://localhost:5173`), `src/log.ts` (logger con niveles info/warn/error, sin datos personales).
- `GET /health` responde lo que valida `healthResponseSchema`. CORS de Express y de Socket.IO restringido a `CLIENT_ORIGIN`.
- Dev con `tsx watch`; `build` con `tsup` (bundlea `@clave/shared` adentro, ADR-010) para que Render corra JS plano en M8.
- **TDD**: `app.test.ts` — `/health` devuelve 200 y pasa el schema; un `socket.io-client` conecta; un origin no permitido recibe rechazo de CORS.
- `.env.example`.

### T5 — `apps/web` · `feat(web): add vite react app with connection indicator`

- Vite 8 + React 19 + Tailwind 4. `src/index.css` con los tokens de SPEC §5.2 como CSS variables (`--bg`, `--paper`, `--ink`, `--red`, …) y `body` sobre `--bg`. Sin fuentes todavía (M4).
- `src/i18n/es-AR.ts`: `connection.connecting` "Buscando a los agentes…", `connection.connected` "Conectado", `connection.reconnecting` "Se te cortó. Reconectando…" (§3.5).
- `src/net/socket.ts`: cliente Socket.IO con `VITE_SERVER_URL` (default `http://localhost:3001`), reconexión automática.
- `src/store/connection.ts` (Zustand): `status: 'connecting' | 'connected' | 'reconnecting'`.
- `src/components/ConnectionIndicator.tsx` (punto + texto, `role="status"`, `aria-live="polite"`) y `src/screens/Landing.tsx` mínima con el título "Clave".
- Test Vitest (jsdom) del store: transiciones al recibir connect/disconnect.
- `.env.example`.

### T6 — `pnpm dev` y gates · `chore: wire dev script, checks and pre-commit`

- `pnpm dev` = `pnpm -r --parallel --stream dev` (sin agregar `concurrently`).
- Scripts `check:fast` (typecheck + lint + floor-guard), `check:task` (check:fast + `vitest run --coverage`), `check:full` (por ahora = check:task; e2e/axe/size/seguridad se suman en su hito, como dice CONSTRAINTS.md).
- `simple-git-hooks` pre-commit: `pnpm check:fast && pnpm --filter @clave/shared test` (ADR-011: elegido sobre husky por cero archivos extra).
- `README.md` con quick start y comandos.

### T7 — Hooks de Claude (KICKOFF §4) · `chore: add hookify rules`

Propuestas, se instalan solo si aprobás este plan:

1. **Bloquear `git commit --no-verify`** (event `bash`, pattern `git\s+commit.*--no-verify`, action block). El bloqueo por typecheck/tests ya lo hace el pre-commit de T6, que además cubre commits hechos a mano; esta regla evita que el agente lo saltee.
2. **Avisar al editar `SPEC.md`** (event `file`, path `SPEC.md`, action warn: "El SPEC solo cambia con OK de Tomás").
3. **Avisar si se emite estado de cartas sin `toPublicView`** (event `file`, path `apps/server/src/**`, contenido que matchea `emit\(` junto a `cards`/`keyMap`/`\.type` y no contiene `toPublicView`, action warn). Es heurística por regex; la garantía real es el test anti-filtración de M3.

## Cierre del hito

1. `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm check:task` en verde.
2. **Criterio de aceptación**: levantar `pnpm dev`, abrir `http://localhost:5173` con el navegador (Chrome DevTools MCP o Playwright con el Chromium preinstalado), esperar "Conectado", screenshot. Extra: matar el server y verificar "Se te cortó. Reconectando…", levantarlo y volver a "Conectado".
3. Probar el pre-commit: un commit con un `@ts-ignore` de prueba tiene que fallar.
4. Review con subagente `agent-skills:code-reviewer` (correctness + seguridad: CORS, logger).
5. Resumen + qué probar a mano en Linux Mint (`corepack enable`, `pnpm install`, `pnpm dev`).
