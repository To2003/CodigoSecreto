# Plan M1 — Motor de reglas

**Criterio de aceptación (SPEC §12):** tests de todas las reglas pasando, cobertura ≥ 95% en `packages/shared/engine`, partida completa simulable por consola. Además: mazo Clásico ≥ 400 palabras y Argento ≥ 200 (SPEC §7), validación de pistas (§1.6).

## Diseño

- `packages/shared/engine/` — funciones puras, sin I/O.
  - `rng.ts`: `mulberry32(seed)`, `shuffle`, `pick`, `randomId` (IDs de carta aleatorios).
  - `normalize.ts` + `clue.ts`: normalización (minúsculas, sin tildes ni diéresis, `ñ` ≠ `n`, plural básico) y `validateClue(word, unrevealedWords, { allowCompound })` → `{ ok } | { ok: false, reason, conflict? }`. La UI la reusa para validar en vivo.
  - `types.ts`: `GameState`, `Action`, `GameEvent`, `EngineError`.
  - `setup.ts`: armado de partida (equipo inicial, 25 palabras, mapa clave 9/8/7/1, IDs).
  - `engine.ts`: `applyAction(state | null, action, rng) → { ok: true, state, events } | { ok: false, error }`.
  - `simulate.ts`: partida completa con bots por consola (`pnpm --filter @clave/shared simulate [seed]`).
- `packages/shared/schemas/settings.ts`: Zod de la configuración de sala (§1.7).
- `packages/shared/words/{clasico,argento}.json` + `index.ts` + `words.test.ts`.
- El lobby (unirse, equipos, roles) es del server (M2): `START_GAME` recibe `{ players, settings, excludeWords }` ya armados.

## Acciones

`START_GAME`, `GIVE_CLUE`, `POINT_CARD`, `REVEAL_CARD`, `END_GUESSING`, `OBJECT_CLUE`, `VOTE_OBJECTION`, `TIMER_EXPIRED`, `REMATCH` (SPEC §1.8) más `SET_CONNECTED` (de sistema: presencia, para la mayoría y para votar). Las de sistema (`TIMER_EXPIRED`, `SET_CONNECTED`) solo las crea el server; ningún evento de cliente se traduce a ellas.

## Tareas (TDD, un commit cada una)

1. RNG con seed + shuffle (tests de determinismo).
2. Normalización y validación de pistas (todos los casos de §1.6).
3. Schema de settings (Zod) + tipos del motor.
4. Mazos Clásico (≥ 400) y Argento (≥ 200) + test de calidad.
5. Setup de partida (`START_GAME`): validación de equipos, palabras, mapa clave.
6. Pista y adivinanza: `GIVE_CLUE`, `POINT_CARD`, `REVEAL_CARD`, `END_GUESSING`, victoria/derrota.
7. Objeciones: `OBJECT_CLUE`, `VOTE_OBJECTION`, resolución.
8. Timers, presencia y revancha: `TIMER_EXPIRED`, `SET_CONNECTED`, `REMATCH` con rotación de jefes.
9. Simulación por consola + umbral de cobertura 95% en `vitest.config.ts` + code-simplification.
