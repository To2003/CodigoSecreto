# Plan M2 — Salas y lobby

**Criterio de aceptación (SPEC §12):** 4 pestañas arman equipos; F5 conserva el lugar; cambiar de equipo se ve en todas en < 200 ms local.

## Contrato (packages/shared/schemas/events.ts)

- Cliente → server, todos con ack `{ ok: true, … } | { ok: false, error: { code, message } }` y validados con Zod:
  `room:create`, `room:join`, `room:leave`, `lobby:setTeam`, `lobby:setRole`, `lobby:randomize`, `lobby:updateSettings`, `lobby:kick`.
- Server → cliente: `room:state` (vista completa filtrada) y `room:patch` (`{ seq, view, events }`), `room:kicked`.
- ADR-019: el patch lleva la vista filtrada completa (no un diff JSON) más la lista de eventos; el `seq` sigue detectando saltos.

## Server (apps/server/src)

- `rooms/codes.ts`: códigos de 4 letras sin `O`, `I`, `L` (crypto).
- `rooms/room.ts`: lógica pura de sala (crear, unirse, reconectar por token, salir, equipo, rol, sortear, settings, expulsar, host que pasa al más antiguo, 16 jugadores máx., `canStart` con motivos).
- `rooms/store.ts`: `Map` de salas, barrido de salas vacías tras 30 min y de desconectados tras 60 s.
- `handlers/lobby.ts`: Socket.IO + Zod + rate limit (20 eventos/s por socket).
- `views/roomView.ts`: lo que ve cada jugador (sin tokens de nadie).
- Sanitización de apodos (§2.5): trim, sin caracteres de control ni `<>`, 1–20 caracteres.

## Web (apps/web/src)

- Router mínimo con History API: `/` y `/sala/:código`.
- `net/client.ts`: emits con ack como promesas, `seq`, reconexión con token guardado en `localStorage` por sala.
- `store/room.ts`; pantallas Landing (crear/unirse), Perfil (apodo, avatar 1–12, color; recordado) y Lobby (Rojo / Azul / Espectadores, jefe y agentes, configuración editable solo por el host, "Empezar" deshabilitado con el motivo, copiar link y compartir).
- El arte de avatares y el layout final son de M4; acá van placeholders accesibles.

## Verificación

- Unit (Vitest): lógica de sala, códigos, sanitización, vistas.
- Integración (Vitest + socket.io-client): handlers, Zod, ack de errores, reconexión por token, kick, rate limit.
- E2E (Playwright, 4 contextos): armar equipos, F5, latencia del cambio de equipo.
